# 意图：像原生一样稳定地把模块交给 Codex 实现

> 经用户在 mc-coord 会话里逐条拷问后确认（2026-10-27，用户原话「对」）。
> 取代 crew-codex-offload（0.16.0）的「模块协调代调用、每个 Task 新开一次 Codex」做法；修订该模块时以本文为准。

- **目标**：Claude 额度**紧张**（不是用完）时，Claude 模块会话可以把一个模块的实现交给 Codex 做，开发效果接近 Claude 原生——稳定、能持续做完，不只是能调用。
- **谁受益**：用户本人，多模块并行、Claude 额度撑不满所有模块的时候。
- **怎么触发**：由用户决定。打开开关 `codexOffload`，或口头说「下一个模块交给 Codex」；口头说了就同步把开关打开，之后的模块默认交给 Codex，直到用户说关。
- **交接点**：**每个模块开工写代码之前**（收到开工通知那一刻）看开关；开着才交给 Codex。已经开始写代码的模块一律由 Claude 做完，绝不中途切换。并行开几个模块都按这一条。
- **分工**：
  - Claude 模块会话：写 Spec、Plan；每个 Task 回来核对 diff、跑快检查、提交；最终验收。
  - **同一个 Codex 会话**：从这个模块的第一个 Task 一直做到最后一个 Task，上下文不断。
  - 模块协调：只转达用户答复、记账、合并，不调 Codex、不代提交。
- **出问题时**：同一个 Task 连续 2 次没通过（核对不过、超时续跑用完、认不出的状态），这个 Task 退回由 Claude 模块会话自己写，同时告诉用户；下一个 Task 照旧交给 Codex。认不出的状态一律不当成完成。
- **怎么算成功**（LIVE-SAAS 试点实测，和 Claude 自己写的模块对比）：
  - 质量不低于原生：合并检查失败、最终验收被用户退回、返工轮次都不更多；
  - Claude 额度至少省一半；
  - 除了 Spec、Plan、最终验收三次批准，中途打扰用户不超过 2 次。
- **前提约束**：delegate 先支持「跨 Task 接着同一个 Codex 会话」、超过 540 秒的任务、结构化结果与机器执行检查命令；没到位之前外包开关不推荐打开、试点不开，不用「前情提要」之类的降级办法凑合。
- **不做**：Claude 额度用完后的接手（属于整体换到 Codex，暂不做）；模块中途在 Claude 与 Codex 之间切换；模块协调替模块调 Codex 或代提交；不等 delegate 到位就降级上线。
