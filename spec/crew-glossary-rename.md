# Spec: crew-glossary-rename

<!-- spec-guard: review pending -->

> 能力图模块 `crew-glossary-rename`（第四版，0.4.0 三个模块之三，也是 0.4.0 的收尾）。需求来源：`livesaas-integration/GLOSSARY.md` 术语表 v1.1（用户决定 48）；
> 0.3.0 冻结时用户定全面改名放下一版。用户 2026-10-19 在本会话确认 19 条下一版假设（全部按推荐）。契约 session-protocol v2.1 不变。

## 目标

用户在 module-crew 里看到的每一处文字——README、命令说明、skill、命令输出、module-crew 生成的消息里的自由文字——都用术语表 v1.1 的名称，和 decision-inbox、spec-guard 说同一套话；
代码标识符、命令与选项名、状态库字段、契约标签与契约字段名一个都不动，所以已有的状态库、脚本和别的插件照常能用。

## 范围

- 改：`README.md`；`skills/crew-coordinator`、`skills/crew-dev`、`codex-skills/crew-dev` 三份 SKILL.md（含 description）；`module_crew/__main__.py` 的命令帮助文字；
  `module_crew/*.py` 里给人看的字符串（命令输出、`status`、钩子注入文字、开工说明、通知与【等待用户】等消息里的自由文字），`protocol.py` 除外。
- 等待记录的显示前缀由 C 改为 W；接收等待记录编号的命令认 `W25`、`C25`、`25`。
- 新增旧称扫描测试。
- 收尾 0.4.0：`plugin.json`／`interface.json` 版本升到 0.4.0（契约仍 2.1），README 写 0.4.0 的变化。

不改：代码标识符、命令名与选项名（`--for-hub`、`source --kind hub|lead`、`ticket`、`inbox` 等）、状态库字段与取值、`protocol.py`（契约的标签、字段名、解析与生成）、
`spec/`、`tasks/`、`docs/` 里的历史文件、提交记录。不顺带改行为（只改文字），不修 pilot 遗留缺陷。

## 假设（用户 2026-10-19 已确认，摘本模块相关的）

15. 改的范围与不改的范围如上。
16. 契约标签出现在给人看的文字里时，第一次写「新名称（契约标签【旧】）」，如「已结项（契约标签【已恢复】）」；skill 里要求会话发出的标签照契约原样写。
17. 等待记录显示前缀由 C 改为 W，编号序列不变（仍与其他记录共用计数器）；接收编号的命令同时认 `W25` 和 `25`。
18. 加扫描测试：README、skill 与输出模板出现术语表旧称就失败；豁免只放契约标签、契约字段与代码标识符。
2. 版本 0.4.0；契约 v2.1 不变。

## 关键决策与取舍（请重点审）

1. **module-crew 用得到的名称对照**（只列 module-crew 里出现过的旧称）：

   | 旧称 | 新名称 | 备注 |

   | 收件枢纽事项、枢纽事项 #H | 待决事项 #H | 只有它用 `#数字` |
   | 负责人、审查会话、lead（文字里） | 审查者 | 「插件负责人」「契约负责人」不出现在给用户看的文字里 |
   | 负责人转交 | 审查者转交 | 契约标签【负责人转交】照旧 |
   | 总协调 | 跨线协调 | |
   | 身份名、短名 | 邮箱名、线名 | |

   | 待用户决定 | 待你决定（D 编号） | 【等待用户】的「待用户决定」字段名照旧 |
   | 适用会话 | 适用的线 | 契约字段名照旧 |
   | 等待单 | 等待记录（W 编号） | |

2. **skill 的读者是会话，「你」指会话本身**：术语表里「你的答复」「待你决定」是对用户说的。skill 里照术语表的名称写成带引号的专名，并在「你的答复」处写成「用户的答复（术语表：你的答复）」，
   第一次出现时写清；命令输出与 README 的读者是用户，直接用「你的答复」「待你决定」。
3. **契约部分原样保留并标注**：`protocol.py` 一字不改；其他文件里，`【…】` 标签与契约字段名（「待用户决定：」「适用会话：」「要你决定：」等）保留原写法；
   给人看的说明第一次提到它们时写「新名称（契约标签【旧】）」或「待你决定（字段名：待用户决定）」。生成的消息仍过 `protocol.parse`，契约一致性测试照常通过。
4. **W 前缀只是显示**：等待记录（`kind: ticket`）在输出、`status`、`sessions` 与消息自由文字里写 `W<号>`；`refs.parse` 对等待记录参数认 `W`、`C` 前缀与裸数字；编号计数器、状态库键、`--json` 数字字段不变，
   `--json` 里给等待记录加 `ref: "W<号>"`（与交审的 `ref: "C<号>"` 同法）。其他记录仍是 C。
5. **扫描测试是护栏，不是翻译器**：`tests/test_glossary.py` 扫 README、三份 SKILL.md、`__main__.py` 的帮助文字与 `module_crew/*.py`（不含 `protocol.py`）的字符串常量；先去掉 `【…】` 标签与契约字段名，再查旧称清单（关键决策 1 左列，去掉「评审节奏」等豁免词），
   命中就报文件与原文片段。豁免清单写在测试里，每条带理由；不扫 `spec/`、`tasks/`、`docs/`、测试文件本身。
6. **对别的插件的影响**：decision-inbox 只按契约标签与字段解析 module-crew 的消息，自由文字改名不影响解析；`sessions --json` 只加 `ref` 不改字段。Spec 写明，发版后回告 decision-inbox。
7. **收尾 0.4.0**：本模块最后一个任务升版本号、README 写「0.4.0 的变化」（停滞事实出口、权限预配与推送守门、术语改名），并在冻结前列出逐项勾清单（需求 R14、R16、改名逐条对应证据）。
   冻结（打标签、固定副本 `module-crew-release/`）与抄送监测会话不在本模块，最终验收后另行请用户批准。

## 接口约定

命令、选项、退出码都不变。变化只有：

- 输出文字按关键决策 1 换名；等待记录编号显示为 `W<号>`。
- 接收等待记录编号的参数（`ticket close`、`answer` 遇到等待记录时的报错提示等）认 `W25`、`C25`、`25`。
- `sessions --json` 与 `status --json` 中等待记录加 `ref`；其他字段不变，`schemaVersion` 仍为 1。
- `interface.json` 的 `version` 为 0.4.0，`contract` 仍为 2.1。

## 边界

- **总是**：只改文字；契约标签与字段名、代码标识符、命令与选项名、状态库原样；生成的消息过契约自检。
- **先问**：改契约标签或字段名（由契约负责人评估）；改命令或选项名；动历史文件。
